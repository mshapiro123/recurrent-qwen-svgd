## 2. Section-9 resolutions

**Q1 — Canonicalizer: Option C first, seed-controlled, with the decision rule preregistered now (amended r2 per Mark's implementation correction, 2026-08-04).** The code shows the `tucker_predictive` arm is not a separate Tucker factorization: it pools the layers with the learned mixture `[0.584, 0.332, 0.084]` and then runs the *same* predictive RRR fit under a different randomized-SVD seed. The comparison therefore has exactly two axes — layer mixture and SVD seed noise — and **no factorization axis**. The design correction is adopted as binding: the free arbitration must isolate the mixture, which means seed control. Protocol, authorized immediately (CPU, cached outputs, private records): (a) **deterministic SVD preferred** — if the whitened cross-covariance dimensions permit an exact (LAPACK) decomposition, run both arms deterministically and remove seed noise entirely; otherwise fix one common randomized-SVD seed across both arms and add a three-seed spread report per arm to size the fit noise. (b) Arms, identical in every other respect: **uniform-mixture RRR** (1/3, 1/3, 1/3) versus **learned-mixture RRR** (`[0.584, 0.332, 0.084]`). (c) Decision rule, unchanged in form and now cleanly interpretable as "does the learned mixture earn its place": paired bootstrap 95 percent CI on Δ(teacher top-1 agreement) on the document-disjoint holdout with sign consistency across workload strata — CI excludes zero → **learned-mixture RRR primary**; otherwise **uniform-mixture RRR primary** on parsimony. (d) If the multi-seed spread (where deterministic SVD is infeasible) is comparable to the previously reported 0.68pp edge, that finding is banked on its own: the screen's apparent Tucker advantage was within fit noise, and the equivalence branch of the rule applies without further argument. (e) **Ledger rename**: `tucker_predictive` → `learned_mixture_rrr` in prose and future receipts (same signed-artifact convention as the `screening_survivor` rename); the manuscript must never describe this arm as a Tucker factorization. The previously authorized mixture-transplant refit is subsumed — it is arm (b). Option B (six-arm pilot matrix) remains rejected. The mid-stack observation stands unweakened — the near-abandonment of the late layer (weight 0.084) derives from the learned mixture itself, not from any factorization — and remains worth a sentence in the paper.

**Q2 — The 55 percent monotone fraction is adequate; no design amendment; build-only proceeds.** The non-monotone 45 percent is not a defect discovered in the design — it is the phenomenon the design exists for. The architecture's load-bearing members (per-position gate, masked-improvement loss, bounded writeback, acceptance verification) were installed precisely because average-helpful directions are individually harmful at material rates; that is the program's oldest measured lesson, now confirmed in state space. Monotone KL along an *affine* path is also a strictly harder requirement than the module faces: the trained flow needs gated endpoint improvement, not straight-line monotonicity. One addition, so the concern becomes a measured quantity instead of a worry: the matched pilots must report the **trained-module analogue** — per-example fraction of accepted updates that worsen probe KL and final-answer quality, stratified by gate state — read against these 0B path numbers as the untrained baseline.

**Q3 — alpha = 0 stays in the pilot matrix.** All three arms run. The two probe-KL regressions and the extreme anisotropy are predictions about how alpha = 0 fails on the full objective, and the A35 ablation is the only stage that can test them where they matter — under real losses, per-module clipping, fp32, and acceptance measurement. Retiring the arm now would spend the control precisely when it becomes informative. Preregister the prediction in the pilot protocol: strategy expects alpha = 0 to underperform on stability diagnostics (clip fraction, gradient balance) and to fail decision alignment; if it instead wins on acceptance, that is a real discovery about equalization and the registered default is wrong. Cost is one-third of a cheap DEV pilot; the r3 shared-basis assertion (only Lambda^(−alpha/2) differs across arms) continues to bind.

**Q4 — Selection rule: the lexicographic form is adopted with one amendment — quality is a gate, not a rank axis.** Final form, binding in the pilot protocol: (1) exclude any arm violating identity, frozen-lineage, tube, or preservation assertions; (2) among valid arms, require final-answer/upper-model quality **non-inferiority versus zero-loop** (the existing two-tier margin applies) — quality does not rank arms, it disqualifies them; (3) rank the qualifying arms by **verified acceptance** (the program's registered currency) on the matched DEV set; (4) tie-breakers, in order: flow convergence, gradient balance, clipping burden; (5) practical-equivalence band: two arms are equivalent when the paired bootstrap 95 percent CI on Δ(mean accepted length) lies within **±2 percent relative**, or when between-seed variance exceeds the between-arm difference — in either case **alpha = 0.5 is retained as the registered default** rather than selecting on noise. Seeds: minimum 2 per arm, identical seed set across arms; if the two-seed spread already exceeds the arm differences, that is the equivalence outcome, not a reason to add seeds mid-protocol. Bands, budget, seeds, and stopping rules are written into the protocol before the first pilot step, per the handoff's own requirement.

## 3. The alpha grid question (Mark, 2026-08-04)

Mark's observation is correct: three points is a screen, not a grid search, and the current data cannot select alpha. The design already agrees — 0A/0B screened for numerical validity only, and selection was always deferred to the built-module pilots. The strategic question is whether to densify the grid before the pilots, and the answer is no, for a measured reason: the 0A alpha response was flat in every fidelity metric and smooth/monotone in the optimization-geometry metrics, so intermediate points would multiply pilot cost without adding discrimination on anything that currently varies. Densification is warranted only if the pilots surface structure the screen could not see. **Preregistered refinement trigger:** if alpha = 1.0 beats alpha = 0.5 outside the equivalence band on the primary criterion, one additional arm at alpha = 0.75 runs before the selection locks (and symmetrically, alpha = 0.25 if 0 beats 0.5 outside the band — the predicted-unlikely branch). If the winner is 0.5 or the band holds, the three-point screen was sufficient and the default stands.

## 6. Plain-language summary

The screening experiments came back positive but appropriately modest: the big teacher's future behavior really can be squeezed into a small learned summary — supervised methods double the useful signal over the naive baseline — and a tiny module really can learn to walk that summary toward where the teacher ends up. But the walk helps only on average: on nearly half of individual examples the straight-line path wobbles, and making the summary better sometimes makes the actual next-word decision slightly worse. None of that is bad news for the design, because the design never trusted averages — the gate, the caps, and the accept/reject check exist precisely for this. So the decisions are: run the free statistical comparison before choosing between the two best compression methods rather than crowning a winner on a hair's-width margin — and, per Mark's code finding, run it with matched randomness, because the two methods turned out to differ only in how they blend the teacher's layers plus the luck of a random seed; build the full machine now with no training attached and prove its plumbing; keep all three whitening settings for the real test, with a written rule for how the winner is chosen and a default that wins ties so noise can't decide; and keep the reserved-but-empty slots for future trace data. Training still waits for the one missing safety report (V1d) and a locked test plan.
