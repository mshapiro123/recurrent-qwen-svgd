## 0. Plain-language summary

Four more boundaries, and one of them turned out to be an error in the ratified build handoff rather than in the code. The implementation scales attention logits by one over the square root of the head dimension; the handoff says one over the head dimension, citing μP. Both are "μP" — the difference is base shapes. μP is defined so that at the base width it coincides with standard parameterization and then rescales as width multiplies; the textbook 1/d form assumes the head dimension itself is the width being scaled. In WEFT-1 the head dimension is fixed at 64 at both proxy and target — width scales through the number of heads — so the base-shape form of the μP attention scale is √64/64, which is numerically exactly the 1/√d the code already uses. The handoff wrote the textbook line; the code implements the base-shape line; the code is the μP-correct one. But the handoff is ratified and the code is not authority, so the reconciliation is a decision for Mark, with a strong recommendation to amend the handoff to the base-shape form: no behavioral change, no silent patch, μP-correct if the head dimension ever does scale, and the existing square-root test becomes the ratified test.

The width diagnostic that accompanied the catch ran under choices that do not match the model's real scaling axis — fixed head count with shrinking heads, lanes at the wrong fraction — so its large drift numbers are evidence that the protocol was unbound, not evidence about the parameterization. The protocol is bound now: head dimension fixed, heads scale with width, lanes at a quarter of width, and the μP initialization and learning-rate rules exactly as the handoff binds them.

The bf16 precision threshold gets its estimand: vector-relative L2, per tensor, per visit, with the terminal visit as the decision value, and two thresholds by category — one percent for the quantities the loss reads, five percent for lanes and gradients, which are inherently noisier under autocast and are absorbed by fp32 masters. I am binding these after seeing the numbers, and I say so; the reason for the two categories is principled, and the data happen to pass. The determinism and structural-flag gates stay complete, with the bounded CPU subset recorded as exactly that — coding's recommendation, adopted. The receipt-schema check was right to refuse "schema complete": field presence is not emission. The fast-weight line is struck from it, the certificate line is pending its own catch, and the four G-TOK families must be emitted by a toy run with semantic validations, which are now written down.

# 1. Catch #28 → Catch #32 — the attention coordinate, and the decision (holds pending Mark)

**Verified:** at `d_head = 64`, literal `1/d_head = 0.015625`; `1/√d_head = 0.125`; **base-shape μP** `√(d_base)/d_head` with `d_base = 64` **= 0.125** — identical to the implemented scale. Under the literal form, initial attention-logit standard deviation at unit-variance q, k is 0.125 instead of 1.0: an 8× cooler start with no μP justification when `d_head` does not scale.

**The principle:** μP is a reparameterization relative to base shapes such that the base-width model *is* the standard-parameterization model; the `1/d_head` attention rule (Tensor Programs V, Table 3) is the width-scaling of `1/√d_head` when `d_head` is the dimension being multiplied. WEFT-1 scales width through head *count* (8Q/4KV at 512 → 16Q/8KV at 1024) with `d_head = 64` fixed; the base-shape attention scale is therefore `√(d_base)/d_head = 1/√64` at every width the program trains. **The handoff's §8.1 wrote the textbook line without base shapes — catch #32, strategy's.** The code is μP-correct; the ratified text is not; and code is not authority, so:
