## 1. Corrections C1–C4 (the four required items)

**C1 — Receipt language corrected; strategy concedes the overstatement.** The correct statements, which replace the handoff's §2 items 1 and 3 and all echoes of them in program documents and figures:

- 60.85% is the oracle-aimed **teacher-token top-1 flip rate at selected token positions** at the measured safe radius. It is not a final-answer result.
- +3.91 and +5.61 points are **per-position teacher-agreement gains** under oracle aiming. They are not task-answer accuracy ceilings.
- 98.4% applies to the **closest-distance quartile only**, not the population.
- The corrected rationale sentence: *the channel has substantial token-level causal reach; whether token-level reach converts to task-answer improvement is Phase 3's hypothesis, and gap_closed is the measurement of exactly that conversion.* This makes the P3.3→P3.4 arc more honest and, usefully, more informative: a positive gap_closed would now be a discovery rather than a collection.

This correction is itself an instance of the standing receipts rule — quantities travel with their receipt fields, and these three traveled without them. The rule now explicitly covers *claim scope* (what the number is a measurement *of*), not only magnitude and provenance.

**C2 — Per-position gate head: authorized as a Phase 3 architecture change.** Acknowledged: the current bridge (paper2_dc2_student.py:250) has one learned scalar gate per loop, position-independent, and the control state is not a bridge input. The charter's gate_p is therefore a build, not a description. Authorization and contract:

- New per-position gate head taking (h_p, S, control state) as specified in the charter's §4. Control-state projection **zero-initialized** so it contributes nothing at init.
- **Initialization by scalar migration:** the Phase 2 checkpoint's per-loop scalar gate value migrates into the new head's per-loop bias, position-dependent weights zero-initialized. At init the new head reproduces the old gate exactly (position-uniform, equal to the trained scalar), so the migrated model's writeback matches the Phase 2 checkpoint on the standard audit batch — that equivalence check, plus the zero-loop bit-exact identity, are the required migration tests before any P3.3 training step.
- The **1,184,917** count is the Phase 2 sidecar receipt and is frozen as such. The Phase 3 trainable count is established by the gate-head build receipt and becomes the number all subsequent documents carry. Figure r2 says this explicitly.
- Checkpoint migration is one-way and hash-ledgered: source checkpoint hash, migration script hash, migrated checkpoint hash, all in the build receipt.

**C3 — Label semantics rebuilt on what the lattice actually contains.** Acknowledged: the cache's verifier semantics are observed-token-only, the Stage 0A receipt reports verifier_only = 0, and a standing do-not-claim already bars equating teacher agreement with correctness. The charter's "teacher-right/student-wrong," "teacher_wrong," and verified-answer L_CE were written against labels that do not exist. The corrected data architecture is two strata with honest semantics:

- **Agreement stratum** (the existing 181,969-anchor lattice). Observable labels only: teacher/student top-1 disagreement, teachability T(K), confident agreement. Supplies L_KL (unmasked — distilling toward the teacher on unverified positions is the standard KD bet, and its limitation is now stated rather than papered over by a mask that could not be computed), the oracle direction d* (defined toward the teacher token — an **agreement-directed** signal, and named as such), and gate labels per the tri-state rule below. The preservation loss is redefined onto **confident-agreement positions** (observable), replacing "student-correct."
- **Verified stratum** (new, assembled in P3.1). Training splits of the same battery families with programmatic verification: gold-answer checking for ARC and the math set, unit-test execution for the code set. Document-disjoint from DEV and CONFIRM halves. Here teacher-right/student-wrong and teacher-wrong are real labels. Supplies L_CE, the A4 verifier mask (which is hereby scoped to this stratum — on the agreement stratum it is undefined and not applied), verified gate positives, and verified audit slices for the π estimators wherever coverage permits.
- **Tri-state gate labels, adopted verbatim:** positive (flip candidates per each stratum's semantics — verified teacher-right/student-wrong on the verified stratum, high-teachability disagreement on the agreement stratum), negative (confident agreement with a margin criterion set in the lock), **ignored** (everything else). L_gate is computed over positives and negatives only. No non-positive row is ever treated as a closure label by default.

**C4 — False-stop rule replaced with the paired sequential design.** The r2 computation (squared single-eval binomial) is withdrawn — the events are correlated through shared rows and adjacent checkpoints, and ~20 looks add multiplicity. Adopted rule, verbatim from the review: the floor fires only when the **one-sided upper confidence bound for the paired (augmented − base) difference is below −3 points on two consecutive evaluations**, with the confidence level and battery size set by **simulation under the actual paired design and look schedule**, targeting a familywise false-stop probability below 1 in 10,000 over the campaign under the null. The simulation code, seed, and result are a P3.1 deliverable and appear in the lock beside the threshold — the estimator-in-the-same-clause rule applied to the one cliff.

## 2. Adopted amendments B1–B6

- **B1 — π decomposed into three reported quantities.** π_dir: forced-open direction capture (cosine/flip capture with gate forced open, magnitude at the standard bound) — measures whether the bridge can aim at all. Gate operating statistics: recall and precision against the tri-state labels at the current ceiling. π_dep: deployed capture — flip-rate ratio with the model's realized gate and magnitude. **The O1 falsifier readings (≥ 0.25 proceed, < 0.05 boundary) apply to π_dir**, because O1 asks whether aim is learnable. **The annealing controller's rung requirements key on π_dep and χ**, because rung advancement is a deployment-safety question. All three appear in every report-back.
- **B2 — Oracle denominator, both accountings.** Adopted: the oracle flip rate is reported both forced-open (matching π_dir's numerator conditions) and under the model's realized gate and magnitude (matching π_dep's). No mixed-condition ratio is ever formed.
- **B3 — Write formula: code is canonical.** The bridge forward equation as implemented (delta normalized to capped state RMS, multiplied by the gate) is the canonical definition. The P3.3 lock reproduces it verbatim from source with every symbol bound to its receipt (c = 0.15, the p99 reference 0.550893, ρ, and the controller ceiling γ defined as an upper clamp on the gate output). The charter's and figures' shorthand is subordinate to the lock's equation. No document invents a variant of the write bound again.
- **B4 — Macro and micro pooled accounting, both required.** The claim-coherence requirement now reads: the confirmed "better model" claim requires the **macro** pooled delta (fixed per-battery weights, locked in P3.1 before any scoring — default equal weights across the named batteries unless the lock registers otherwise) **and** the **micro** pooled delta (item-count weighted) to both be non-negative. Battery size no longer determines scientific importance, and cherry-picking a favorable weighting after the fact is impossible because the weights predate the scores.
- **B5 — The ridge probe is a linear-decodability forecast.** Renamed accordingly everywhere. It is neither an upper bound (the bridge is nonlinear and may exceed it) nor a lower bound (regularization and finite samples may undershoot). Protocol: document-disjoint holdout, ridge strength selected on a separate calibration split, cosine alignment reported with CI.
- **B6 — CONFIRM's limitation stated.** Sealed CONFIRM halves protect against **analysis reuse and adaptive overfitting by this program**. They do not address benchmark contamination from pretraining, which is possible for any public set and affects the base, teacher, and augmented models through shared pretraining exposure. The paired A_aug − A_base delta is the contamination-robust quantity (both terms share the base's exposure). Teacher-side contamination inflates the gap_closed denominator and is acknowledged in Limitations. This paragraph enters the P3.1 lock and the paper's Limitations section.

## 3. Answers to the seven questions

1. **Receipt-language correction: approved.** C1 is the governing language. The r2 handoff stays landed as the charter record; this amendment supersedes its §2 items 1 and 3; figure r2 carries the corrected captions (quartile qualifier on 98.4%, and the rationale caption softened to token-level reach).
2. **Per-position gate: authorized**, per C2 — scalar-migration initialization, zero-init position weights and control projection, migration equivalence tests mandatory, final parameter count set by the build receipt and adopted program-wide from that receipt forward.
3. **External labels come from the verified stratum built in P3.1:** training splits of the named battery families with programmatic verification (gold answers for ARC and the math set, unit-test execution for the code set), document-disjoint from DEV and CONFIRM. The general/code lattice remains the agreement stratum and is never claimed to carry correctness. If verified coverage proves too thin for L_CE or the verified audit slices, the named escalation is a targeted teacher-cascade verification pass (32B where the cascade provides it) — through a lock, not mid-run.
4. **Batteries, named now for the P3.1 lock to pin:** ARC-Easy and ARC-Challenge (allenai/ai2_arc, the Paper One infrastructure and reader), GSM8K (main config) as the math set with the final-number reader, and MBPP (sanitized) as the code set with the unit-test execution reader. The reference/floor battery: the Paper One Tier-1 style set plus a fixed seeded MMLU slice as the general-knowledge component, sized by the C4 simulation. Exact dataset revisions, reader configurations, and content hashes are pinned in the P3.1 lock. DEV/CONFIRM splits are document-stratified with split seed **20260809**. Training splits of the same families feed the verified stratum and touch no evaluation half.
5. **Macro and micro both non-negative: agreed and adopted** as B4, with weights locked before scoring.
6. **P3.3 initializes from the E1-confirmation checkpoints (the Option B final checkpoints the verdict was read on), both seeds, hash-pinned in the lock.** The gate migrates the trained scalar into the per-loop bias rather than initializing closed: it preserves exact behavioral continuity with the banked checkpoint, makes the migration equivalence test meaningful, and lands the initial gate near σ(−4) ≈ 0.018, inside the rung-0 ceiling of 0.02 — continuity and the annealing schedule agree.
7. **The P3.0 memo is forthcoming as the next strategy deliverable.** It does not block P3.1 or P3.2 builds and will land before the P3.3 loss lock, as the charter requires.
