## 0. Plain-language summary

The watch is right that FarSkip is the most relevant item, and right that it is a systems result before it is a science result. What it shows at scale is that a network does not need every branch's newest output before the next computation starts — a one-layer-late expert contribution cost nothing on benchmarks and bought twelve percent of throughput. Two things need saying before WEFT registers anything. First, WEFT-1 *already* has the temporal separation FarSkip validates: the lanes integrate per block, and the carrier reconciles with the lanes once per visit, the callosum once per visit — the design chose delayed reconciliation at the visit level before this paper. FarSkip is external support for that choice, recorded as such. Second, the analogy breaks quantitatively at the level of a proposed arm: a one-layer delay in a thirty-two-layer stack forfeits three percent of the computation; a one-*visit* delay in a loop of K = 4 forfeits a quarter of it, and at K = 2 half, because the delayed contribution from the last visit never lands. So the delayed-coupling arm is registered, but with the prediction written down that it hurts at small K and only approaches neutrality at large K, and with the throughput argument explicitly not transferring at WEFT's scale (the sidecar is a tenth of a percent of a block). The router-stability items from Instella are cheap and adopted: a receipt line for route stability across visits and between train and eval, and an obligation to record and replay exact selections in any future reinforcement phase.

The context-versus-memory paper is the useful warning. A control direction that is genuinely causal within a task transferred only weakly across tasks — nine percent of the effect against fifty-seven — which says that "semantically generic" latent controls may be task-local coordinates rather than global ones. That qualifies both the compositional-operator hypothesis and the workspace idea, and the fix is the same one this program adopted for memory addressing last week: hierarchy. Coarse family first, local operator second. The diagnostic is bound — within-family versus cross-family coefficient similarity, with the paper's own ratio of 0.16 registered as the pretrained-model prior — and the branch is fixed: if within greatly exceeds cross, hierarchical coefficient addressing becomes MEM-SYN's default. One rule is restated so the watch's proposal does not walk back a ruling: the coefficient map may read a task/address variable, but that variable must be content-anchored, never the raw state — ROW-R1 stands.

LRNBA is the static ancestor of WEFT's operator bank: a shared basis with per-depth coefficients, sitting exactly between independent layers and pure recurrence. It earns one thing — a control arm. Before believing that state-dependent operator synthesis is worth anything, MEM-SYN must beat a learned table of coefficients indexed only by the visit number. Its two stability tricks are examined and found already present or moot: zero-initialized response paths are the gate-only near-identity rule we already use, and dividing reused-basis gradients by the reuse count is a no-op under Adam up to epsilon.

# 1. Instella-MoE / FarSkip — delayed coupling

**What WEFT-1 already does.** Within a visit, lane updates happen per core block (four times), while the carrier write from lanes and the callosum happen **once per visit** (R-4 schedule). The lanes are therefore autonomous for a full visit before rotor-mediated reconciliation — the "partially autonomous branch, deferred mixing" pattern FarSkip validates at 16 B. **Recorded as external support (Tier-2) for the R-4 schedule**; no change.

**The proposed arm, with the arithmetic that qualifies it.** A one-*layer* delay in a ~32-layer stack defers ≈ 3 % of the computation; a one-*visit* delay in a loop defers `1/K` of it and **loses the final visit's contribution outright** (nothing follows it to receive the delayed write): 50 % at K = 2, 25 % at K = 4, 12 % at K = 8. The FarSkip motivation — overlapping communication with computation — does not transfer either: the sidecar is ~0.1 % of a core block, so there is no throughput to buy.

> **DELAY-1 (registered successor arm, MEM-OP family).** Factor: the sidecar's lane write computed at visit k lands **at visit k+1** (delayed) vs at visit k (immediate, as ratified). Everything else fixed; a final-visit "flush" is *not* added (that would make it a different mechanism). **Pre-registered prediction:** delayed loses to immediate on `η_k` at K ≤ 4 and converges toward parity as K grows; the interesting branch is *delayed ≥ immediate at K = 4*, which would mean the sidecar's benefit is temporal decorrelation rather than same-visit correction — reported as a mechanism finding. Instruments: `η_k` vs reallocation, RESP-LEAK, the C-JAC two-number line (a delayed write moves the sidecar factor into the next visit's Jacobian block — the certificate composition is unchanged, the per-visit factorization changes). Queue: with MEM-OP, behind the sidecar battery.

**Router items, adopted as receipts.**

> **ROUTE-STAB (receipt line, sidecar and Hadamard arm).** Per eligible step: (i) fraction of examples whose top-3 selection changes between consecutive visits; (ii) fraction whose selection differs between training mode (straight-through gate) and eval mode on the same input; (iii) for the occupancy router when it exists, the same two under its hysteresis. WEFT's selection is a frozen PQ code over a frozen-standardized descriptor — stability is *structural* by design — so this line is expected to read near zero and exists to catch the case where it does not. Instella's DPO router-bias freeze is the same instinct one level up: frozen measurement constructs (`(m, s)`, codebook, feature standardization — the single calibration gate of S-5) are never updated by a post-training phase.

> **REPLAY-SEL (obligation, P4 / any future RL phase).** The exact selection codes and gate decisions used to generate a token are **recorded in the step receipt and replayed in the update**, so training evaluates the expert path that produced the sample. Cheap now (the receipt fields exist in C7 stage 2's family); expensive to retrofit.

# 2. Context vs memory — task-local control directions

**The finding, in our units.** Within-task direction closes 57 % of the authority gap; cross-task transfer closes 9 %: an **effective cross-task overlap of ≈ 0.16**. A causal control coordinate exists and is local to its task family.

**What it qualifies.** COMP-SKILL (LS-1) assumes operator coefficients `c_A, c_B` extracted on different skills live in one coordinate system and compose; ROW assumes the workspace `w_k` carries a generic "what kind of situation" summary. Both may instead be **family-local coordinates**. This is the operator-side twin of Kathleen's address-side finding, and it gets the same answer — hierarchy.

> **COMP-LOCALITY (diagnostic added to LS-1, pre-registered).** On the verifiable procedural task set, with coefficient vectors `c_i` per example: `C_within = E[cos(c_i, c_j) | T_i = T_j]`, `C_cross = E[cos(c_i, c_j) | T_i ≠ T_j]`, with a permutation null. **Prior registered from the paper: `C_cross / C_within ≈ 0.16`** if WEFT's operator geometry behaves like a pretrained LM's control geometry. **Branches:** `C_within ≫ C_cross` ⇒ **hierarchical coefficient addressing becomes MEM-SYN's default** — a coarse family address selects a sub-bank (or a sub-space of coefficients), the local descriptor selects within it (the KR-3(a) form, now on the operator side); additive composition across families is then expected to *fail* and COMP-SKILL's additive test is reported per family. `C_within ≈ C_cross` ⇒ the global bank stands and cross-family composition is a live hypothesis. **Family labels** in a from-scratch model are not given: the diagnostic uses the task families of the S2 procedural battery, and the *learned* coarse address (the PQ code's leading bits) is tested against them for agreement.

> **Rule restated, so the watch's `c_k = R(h_k, a_k)` does not reopen ROW-R1.** The coefficient map may take a task/address variable `a_k`, but **`a_k` is content-anchored** (KR-3: stable content anchor, or the normalized mixture with its floor) and **the map never reads raw `h_k`** — it reads the workspace `w_k` (ROW-R1). `c_k = R(w_k, a_k)` is admissible; `R(h_k, ·)` is not.

# 3. LRNBA — reusable bases

**The mapping.** `R_l(x) = Σ_j α_{j,l} φ_j(x)` — shared nonlinear bases, coefficients indexed by depth — is the **static ancestor of MEM-SYN**: WEFT's weight-tied core is the shared basis, and the sidecar replaces the depth-indexed table with state-dependent coefficients over low-rank operators. LRNBA's own framing ("between independent layers and identical recurrence") is WEFT's location exactly.

> **MEM-SYN-STATIC (control arm, MEM-OP family).** Coefficients `c_k = α_k`, a learned table indexed **only by visit index k** (K × E parameters), no state dependence — the LRNBA baseline. **MEM-SYN must beat this** before "memory synthesizes the operator" is claimed; if a static per-visit table matches state-dependent synthesis, the sidecar's value is depth-specialization, not memory, and it is reported as such. Cheap; ships with the MEM-OP battery.

**The two stability tricks, examined.** (i) *Dividing reused-basis gradients by the reuse count:* under Adam the update is scale-invariant up to `ε` (verified: g vs g/8 gives identical updates to 1.3e-4 relative) — a **no-op** for WEFT's AdamW bring-up; under Muon, §7 already rules that forward scaling and update size need separate handles. Not adopted. (ii) *Zero-initialized response paths:* verified — the coefficient's gradient is live (3.7) while the basis's gradient is exactly 0 until the coefficient moves; for a shared basis that receives gradient from many sites this is harmless, and it is the **gate-only near-identity pattern §5.13 already prescribes** (small nonzero LayerScale, never zeroed factors). Already present; no change.

**Empirical claims:** the 6× reusable-basis configuration at lower loss with ¾ of the parameters is noted and not used — single seed, d = 512, WikiText-2, and an MSE/CE ambiguity the watch correctly flagged.
